# Irregularity Evidence Status
1 The competition's sample_submission.tif is not a fault-absence file. The rules page says the sample "predicts total fault absence", but its 60,988 positive cells are identical to the training labels. np.array_equal(sample==1, labels==1) → True; 60,988 positives in both. Rules text: problem description ("A sample submission that predicts total fault absence…"). Flag. Do not use the template's 1-values as a baseline. We use it only for footprint, CRS, transform and shape.
2 Feature rasters carry real values outside the official footprint (label/template invalid mask). RTP band 2: 1,540 finite cells outside footprint (range −342 to 514). scripts/run_tensor_lane.py JSON field feature_values_outside_footprint. Masked to NaN in our pipeline. Rules say data outside bounds must be null/NaN.
3 Feature nodata sentinel −3.4028e38 appears inside the footprint in RTP and isostatic bands (3,061 cells). feature_gaps_inside_footprint in docs/results/tensor_lane_results.json. The GeoTIFF nodata tag is −3.4028234663852886e+38. Treated as missing and filled by footprint mean before low-pass. Flag for the organisers.
4 Competition rasters are committed in a public sibling repo (buffedlizard55-lab/GEMSDOE, folder data/bridge/, ~420 MB in parts). The rules grant the data to registered competitors; I did not find a clause permitting redistribution. Rules §A.5 require third-party content to be properly licensed. gh api repos/buffedlizard55-lab/GEMSDOE/contents/data/bridge/manifest.json. Rules: PDF §3.1, §A.5. Legal review needed. We pulled the files locally only (gitignored) and did not copy them into this repository.
5 Sibling repo "audit" JSON labels projections as leaderboard values (e.g. predicted_leaderboard_dti: 0.2747 for the GEMSDOE32 H33-2-B2 file; the file records UNSCORED). docs/downloads/gemsdoe32-h33-h33-2-b2-20261004T220000Z-e5eb6e7e-audit.json in buffedlizard55-lab/GEMSDOE32. Treated as a projection, not a score.
6 Score figures in the brief disagree. The brief lists "Current competition leaderboard GEMSDOE high score: 0.3774" and also "0.3195 is the highest score right now". Brief text (user-supplied). Unresolved. Neither value is organiser-confirmed in this sandbox.
7 The registry overlap rule is saturated. Many registry rasters have ~5.1–5.2 million positive cells (≈ the whole 5.17 M footprint), so almost any dot lies within 3 px of one. Literal application flags 70 of 630 same-grid rasters for any candidate. docs/results/registry_check_E3.json, docs/results/registry_check_tensor_lane_E1.json. The protocol needs a chance-corrected overlap (observed vs expected by registry positive density). Not yet implemented.
8 The strike-prediction test is not a fair comparison as implemented. A ridge is perpendicular to the gradient, and the strike of a 2-D source is also perpendicular to the gradient, so ridge-vs-field agreement is nearly built in. docs/results/tensor_lane_results.json → strike_test (withheld 43.2% vs random ridges 87.6%). Reported as a failed prediction, with this caveat. A pixel-matched redesign is needed.
9 Sign-convention bug found and fixed in this session. Grid rows increase south; azimuths were initially computed as if y were north, mirroring every strike (135° → 45°). Synthetic test tests/test_tensor.py::test_strike_is_north_convention_and_not_mirrored. The fix is in gems/tensor.py. Fixed; regression test added. Earlier numbers in this session were recomputed after the fix.

The protocol asks for derivatives of the RTP magnetic and isostatic gravity grids; the provided derivative bands (tmi_hg, tmi_vg, iso_grav_anom_hg, iso_grav_anom_vg) were not used. Band list from gdal tags. Intentional (recomputed from FFT per the protocol).
