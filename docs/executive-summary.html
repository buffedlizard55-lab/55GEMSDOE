How to make a GEMS submission

The portal accepts a single-band GeoTIFF or a ZIP containing exactly one GeoTIFF. This page explains the required checks and the upload steps. It does not upload anything for you.

Clearance comes before download

A future file will be offered here only after every research and packaging gate passes. A new name or a format-valid file alone is not enough.

  1. Validate the prediction scientifically.
    Use the canonical whole-segment, buffered hide-and-recover evaluator. Recompute catalogue-derived features from visible faults only, mask visible-fault pixels exactly, and report pooled `HOLDOUT-DTI` with evaluator/version, withheld-positive count, and paired 95% CI. Check each feature alone for leakage and test tensor-strike agreement against random ridges.
  2. Check the lane and registry twice.
    Compare the continuous surface before placing dots, then compare final dots. Stop if absolute rank-correlation exceeds 0.90 or more than 70% of dots fall within 3 pixels of one registry raster. The full registry and shared checker are not present in this checkout, so this gate has not run.
  3. Write with the canonical submission writer and verify bytes.
    Do not make a private replacement. Re-open the final TIFF after writing and compare it to the authentic sample/template: one band, float32, matching CRS, shape, bounds, transform, and resolution; values in [0,1] throughout the scored footprint; no NaN/Inf or invalid nodata sentinel inside that footprint; null/NaN outside the bounds as the competition specifies. Record the file SHA-256 and validator receipt.
  4. Publish the exact artifact details.
    The landing page should show the download link, unique submission name, short identifying note (this project limits notes to 140 characters), holdout card, uniqueness receipt, and validator output together. A projection must never be called a score. The current page correctly has no download link.
  5. Upload only after the separate selector approves a slot.
    Do not spend a weekly slot directly from the experiment step. The selector must confirm that the candidate beats the current comparable holdout best and that the weekly cap permits promotion.

Portal steps when an approved TIFF exists

The screen wording below follows the submission form text supplied in the project request; this session did not log into or submit to DrivenData.

  1. Open the DOE GEMS competition page and choose Submit / New submission.
  2. Under File to submit, choose the approved `.tif` file. A `.zip` is acceptable only if it contains a single GeoTIFF.
  3. In Note (optional), paste the published unique submission name and the short approved comment. Never substitute an owner-reported score or model projection for the method note.
  4. Re-check the filename and comment; select Create to send the submission.
  5. Save the organizer's receipt and record its exact value as `ORGANIZER-CONFIRMED`. A public leaderboard row without a receipt linking it to the file is not file attribution.
Do not try this with an unvalidated file.

The user previously saw “Predicted values must be in range [0, 1]”. Without the rejected TIFF and matching sample, this review cannot diagnose that exact upload. Possible causes include a real out-of-range value, infinity, or NaN inside the scored footprint. Verify the whole footprint and the exact grid; do not infer the cause from a filename.

The official problem page permits null/NaN outside the submitted bounds, but the scored interior still must contain valid probability/confidence values in [0,1]. Follow the authentic sample and canonical writer.
