Method and implementation limits

E1 implemented and run (2026-10-09)

The tensor-dimensionality lane in src/gems55/ was implemented end to end and evaluated under the required protocol: a label-free surface from competition bands 2 and 13, a whole-segment hide-and-recover holdout, an independent-fault proxy sweep, a leakage canary, and a unique format-valid submission (download & submission). The surface and emission code lives in src/gems55/; the experiment drivers are scripts/build_surface.py, scripts/run_holdout.py, scripts/eval_proxy.py, scripts/policies.py, and scripts/build_submission.py.

Implemented method (E1)

  1. Read RTP-magnetic band 2 and isostatic-gravity band 13 from the pin-verified competition feature stack; both grids share the valid-data mask (5,165,852 cells inside the footprint).
  2. Fill invalid cells (nearest valid), then low-pass each field (400 m Gaussian) before differentiating — derivative noise is amplified by FFT differentiation.
  3. Compute each field's horizontal and vertical derivatives by FFT and form the per-pixel symmetric gradient tensor; compute eigenvalues/eigenvectors (tensor55.sym3_eigh).
  4. Map the Pedersen–Rasmussen dimensionality index (0 = strike-extended 2-D source) and the intermediate-eigenvector strike; keep gradient ridges that are near-2-D whose eigenvector strike agrees with the ridge's own orientation; down-weight compact 3-D signatures; weight by plunge.
  5. Mask east–west flight-line striping with a long-lag (60 px) dual-direction coherence test (axis-aligned coherent linear features in both axis directions), because striping is one-dimensional by construction.
  6. Combine the two fields (corroborated ridge rank × near-2-D × strike agreement × plunge, minus striping) into a continuous score surface; cache per-field products to disk (memory-frugal two-phase build).
  7. Emit the submission from the score's top NMS peaks (3-px separation, off-catalogue pixel-exact), the policy selected by the holdout and proxy evidence among 16 swept policies.

Known implementation limits

  • LaneConfig.block_px=64 controls robust normalization in regular pixel tiles. It is not an official GeoDAWN acquisition-block mask; the valid-data mask is one connected blob, so per-acquisition-block processing is not possible with the staged data.
  • Striping direction is ambiguous in the data (spectral test weakly favors N–S lines; profile-variance test favors E–W lines; the dominant 150–800 m spectral energy is at k-azimuth 47.5°, i.e. NW–SE Basin-and-Range geology). The lane asserts E–W flight lines; destriping direction barely changes the residual long-lag coherence, and the dual-direction coherence mask is the operative striping control.
  • The magnetic derivative is a direct-RTP tensor proxy; no pseudogravity transform for a known magnetization direction is claimed.
  • The strike mechanism is not validated (IR-55-046): withheld faults' strikes match the tensor strike on 5.9% of withheld pixels vs 28.9% for random locations (axial chance 22%). The holdout win comes from the ridge/dimensionality/striping components.
  • The local evaluator (gems55.dti55/2.0-local) is a repository-local transcription, regression-tested against a brute-force reference and the official worked example; it is not the organizer's executable and is not certified as the authorized shared evaluator.
  • The greedy cover function optimizes a monotone submodular coverage surrogate, not the exact DTI ratio.
  • Passing synthetic unit tests verifies code properties only; it is not geological validation, an official evaluator match, or a submission clearance.
